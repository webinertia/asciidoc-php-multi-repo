## Summary

Close the alignment gap on `webware/asciidoc-php-multi-repo`, a package that was scaffolded ad hoc
and never derived from `webinertia/repo-template`. The repository gains the full alignment layer:
`webware-ci.json` with package-specific values, a Mago toolchain that extends the shared
`webware/webware-tools` configuration (replacing PHPStan level 10), PHPUnit 13 strict
configuration that keeps this package's two suites, Infection/Codecov/Renovate/PHPBench config
files, `.gitattributes`, `.gitignore`, `mago.bat`, `.devcontainer/devcontainer.json`,
`.github/copilot-instructions.md`, generated lint and analysis baselines carrying the onboarding
remainder, and the standard README badge block.

The container stack (`Dockerfile`, `compose.yml`, `.dockerignore`) and the `webware/asciidoc-php`
Packagist move landed on `1.0.x` through PR #2 and PR #3. This plan verifies those artifacts against
the canonical copies and replaces the transitional `Dockerfile` with the canonical one.

### Test layout (renamed by this feature)

The package shipped `tests/Unit` and `tests/Contract` with the namespace
`Webware\AsciidocPhpMultiRepo\Test\`. The preset convention is singular `test` with two suites, so
the tree becomes:

```text
test/
├── unit/          # WebwareTest\AsciidocPhpMultiRepo\ -> unit test suite
│   └── Support/   # support test cases and shared test doubles
├── integration/   # WebwareTestIntegration\AsciidocPhpMultiRepo\ -> integration test suite
└── fixtures/      # fixture documents, unchanged
```

The former `Contract` suite is mapped onto `integration` because the preset defines exactly two
suites. Its tests assert documentation and schema conformance, so they are contract tests running
under the `integration test` name; no third suite is invented. Because the layout now matches the
preset, deviations D-1, D-2, D-3 and D-7 from the earlier draft disappear, and the
`WARN Failed to walk /app/test` that the mismatch produced no longer appears.

## Reference Mechanics (required workflow contract)

`webinertia/.github` owns `.github/workflows/org-required-ci.yml`; the organization ruleset binds it
to every repository, and that config repository's default branch is the ref it runs at. GitHub
invokes it directly, so a repository cannot pass `with:` inputs: per-package variation arrives as
`webware-ci.json` in the repository root.

- **`webware-ci.json` keys**: `php_versions` (JSON array), `run_integration`,
  `integration_php_version`, `composer_options`, `db_image`, `db_env_json`, `db_port`,
  `db_health_cmd`, `db_health_retries`, `db_health_interval_seconds`, `enable_codecov`,
  `enable_infection`, `coverage_php_version`, `min_msi`, `min_covered_msi`, `test_env_json`.
- **Secrets**: `CODECOV_TOKEN` and `INFECTION_DASHBOARD_API_KEY` are read by the workflow from
  repository or organization secrets; nothing is forwarded per package.
- **Jobs**:
  1. **config**: fails when `webware-ci.json` is absent from the repository root, then publishes
     every key as a job output. Each key has a default, so a misspelled key does not fail the build,
     it silently takes the default. The job also rejects a duplicated Mago version pin; that check
     is skipped in `webinertia/webware-tools` itself, which owns the pin.
  2. **mago**: matrix over `php_versions`; installs Mago at the version resolved from the centre's
     `mago.toml` pin, then runs `mago format --check`, `mago lint`, `mago analyze`, `mago guard`.
  3. **test**: matrix `php_versions` times `[lowest, locked, latest]`; `composer test` on
     non-canonical legs, `composer test-coverage` on the canonical leg (`coverage_php_version` plus
     locked, pcov); `composer test-integration` only when `run_integration`; uploads `clover.xml`.
  4. **codecov**: report-only, `fail_ci_if_error: false`.
  5. **mutation-test**: PHP `coverage_php_version` with pcov, Mago at the resolved pin,
     `composer mutation-test -- --min-msi=... --min-covered-msi=... --logger-github`; Infection
     invokes Mago through `staticAnalysisTool`.

Consumer obligations derived from the contract, all satisfied by this plan:

- `webware-ci.json` exists in the repository root (Phase 5).
- No Mago version literal anywhere in the repository (Phases 3, 7).
- Required composer scripts exist (Phase 1).
- `phpunit.xml.dist` defines the suites the workflow names. This package names them `unit test` and
  `integration test`, matching the preset's two-suite convention; `test` runs every suite and
  `test-integration` targets `integration test`.
- The test layout is conformant: `test/unit` and `test/integration`, namespaces
  `WebwareTest\AsciidocPhpMultiRepo\` and `WebwareTestIntegration\AsciidocPhpMultiRepo\`, matching
  `templates/plan-template.md` Phases 1 and 2.
- `composer.lock` is committed (Phase 1).
- `mago.toml` is present (Phase 3).
- Every configured suite contains at least one test; the two suites already do.

## Deviations from the canonical artifacts

Each deviation is required by this package's actual layout or by the constitution. The PR body
repeats this list. Deviations D-1, D-2, D-3 and D-7 from the earlier draft of this plan are gone:
they existed only because the test directory was named `tests/` and the suites were named
`unit test` and `contract test`. The layout was renamed to the preset convention, so those
accommodations are no longer deviations.

- **D-1 README badges.** The artifact opens with Packagist PHP-version and latest-version badges
  and a License badge. `webware/asciidoc-php-multi-repo` is not published on Packagist (the package
  metadata endpoint returns 404) and the repository carries no `LICENSE` file, so those three
  badges would render as errors. The Required CI badge is kept, pointed at the organization config
  repository's actual workflow. `webinertia/.github` ships `continuous-integration.yml`, not the
  artifact's `org-required-ci.yml`, so the synthetic route is
  `required/webinertia/.github/.github/workflows/continuous-integration.yml`. The codecov and
  Stryker mutation badges are omitted until those reports exist for `1.0.x`. `DEFAULT_BRANCH` is
  `1.0.x`.
- **D-2 Container artifacts.** `compose.yml` and `.dockerignore` are owned by the container session
  and are not edited here. `Dockerfile` is replaced with a byte-identical copy of
  `presets/webware-alignment/artifacts/Dockerfile` (5400 bytes, SHA256
  `0b6a454d24fb24e52781b4ae43a3bc2451a5645045c2535508db24c982f90799`), restoring the Mago install
  stage that `1.0.x` carried only in its transitional 3111-byte form. The stage resolves
  `WEBWARE_TOOLS_REV` from `composer.lock`, fetches `webware-tools/mago.toml` at that revision and
  reads its `version =` pin, so the Mago version keeps exactly one home and no version literal
  exists in this repository.
- **D-3 Guard remediation for the CLI command namespace.** `mago guard` cannot be baselined. The
  shared ruleset reserves `{App,Webware}\**\Command\*` for message-bus commands (final, named
  `*Command`, implementing `Webware\MessageBus\Command\NamedCommandInterface`) and requires
  interfaces to be named `*Interface`. This package's CLI subcommands are neither bus commands nor
  Symfony console commands, so satisfying either bucket would add a dependency this library must not
  carry. The namespace moves from `Webware\AsciidocPhpMultiRepo\Cli\Command` to
  `Webware\AsciidocPhpMultiRepo\Cli\Commands`, and `interface Command` is renamed to
  `interface CommandInterface`. No class is renamed, no behaviour changes, and `contracts/cli.md`
  is untouched because it documents flags, commands and exit codes, not class names.
- **D-4 `mago.toml` source paths name the CLI entry point.** The artifact ships
  `paths = ["src", "test"]`. This package adds `bin/asciidoc-php-multi-repo` so the list becomes
  `["src", "test", "bin/asciidoc-php-multi-repo"]`. The pre-migration `phpstan.neon` analysed
  `src` plus `bin/asciidoc-php-multi-repo`, so dropping the entry point would be a coverage loss
  against the previous state. The path is the file, not the directory: the entry point has no
  `.php` extension, so a `bin` directory entry discovers nothing. `php-version` stays `"8.4.1"` to
  match `config.platform.php` `8.4.99`; `extends`, both baselines and `includes = ["vendor"]` are
  unchanged, and no local `[analyzer] excludes` is needed because the shared config already excludes
  `["test", "bench"]` and this package now uses `test/`.
- **D-5 `composer test` stays unscoped.** `templates/plan-template.md` Phase 1 defines `test` as
  `phpunit --no-coverage --colors=always --testsuite "unit test"`. This package keeps the existing
  unscoped form, `phpunit --no-coverage --colors=always`, so both suites run on every matrix leg.
  That is what makes `run_integration: false` safe: if `test` were scoped to `unit test`, the
  contract suite would run only on the coverage leg, and the required workflow would need
  `run_integration: true` to cover it. `composer test-all` from the preset is shipped as well and
  runs `test`, `test-integration` and `mutation-test` in sequence. The alternative is one line in
  `composer.json` plus one value in `webware-ci.json` if the centre prefers the scoped form.

## Implementation Phases

### Phase 1: composer.json and composer.lock

- Keep `require` exactly as it stands, including `webware/asciidoc-php: ^0.1` and the absence of a
  `repositories` entry. `require.php` stays `~8.4.0 || ~8.5.0`.
- `require-dev`: add `webware/webware-tools` `^1.0.0-rc.8`, `infection/infection` `^0.35.0`,
  `phpbench/phpbench` `^1.7`, `roave/backward-compatibility-check` `^8.21.0`,
  `roave/security-advisories` `dev-master`; remove `phpstan/phpstan`.
- `config.platform.php` stays `8.4.99`. Add `allow-plugins` for `infection/extension-installer`.
- `scripts`:
  - `test`: `phpunit --no-coverage --colors=always` (unchanged; runs every suite)
  - `test-coverage`: `phpunit --colors=always --coverage-clover clover.xml --coverage-text`
  - `test-integration`: `phpunit --no-coverage --colors=always --testsuite "integration test"`
  - `mutation-test`: `infection`
  - The legacy `sa` and `check-all` scripts are removed. `templates/plan-template.md` Phase 1 says
    "No PHPStan package, no PHPStan script; remove legacy `check-all`/`cs-check`/`cs-fix`/`sa`
    scripts", and the preset README invokes the four `mago` commands directly, so no convenience
    wrapper is shipped in their place.
- Regenerate and commit `composer.lock` inside the container so the platform matches.
- PHPStan removal is deferred to Phase 4, after the Mago gates are clean.

### Phase 2: phpunit.xml.dist

- Adopt `bootstrap="vendor/autoload.php"`, `colors="true"`, `cacheDirectory=".phpunit.cache"`,
  `requireCoverageMetadata="true"` and the relative schema pointer
  `vendor/phpunit/phpunit/phpunit.xsd`. The relative path is deliberate: Infection validates the
  config against that schema before running a mutant, so an `https://schema.phpunit.de/...` URL
  makes the mutation job fail whenever the host is unreachable and silently pins a schema series
  that drifts from the installed PHPUnit.
- Keep suites `unit test` over `test/unit` and `integration test` over `test/integration`. The
  former `contract test` suite is mapped onto `integration test` because the preset defines exactly
  two suites; the tests themselves are documentation and schema contract tests, not network
  integration tests, and that mapping is stated in the PR body rather than hidden.
- Keep `failOnNotice`, `failOnWarning`, `failOnRisky`; add `failOnDeprecation` from the artifact.
- `<source restrictNotices="true" ignoreIndirectDeprecations="true">` including `src`.
- Adding `requireCoverageMetadata` means every test class needs `#[CoversClass]` or
  `#[CoversMethod]`; Phase 4 adds the attributes and Phase 5 documents the rule.

### Phase 3: Mago tooling

- `mago.toml` (new): `extends = "vendor/webware/webware-tools/mago.toml"`, `php-version =
  "8.4.1"`, `[linter] baseline = "lint-baseline.toml"`, `[analyzer] baseline =
  "analysis-baseline.toml"`, `[source] paths = ["src", "test", "bin/asciidoc-php-multi-repo"]`,
  `includes = ["vendor"]`. No local `version =`, no schema URL, no local `[analyzer] excludes`.
- `lint-baseline.toml` and `analysis-baseline.toml`: generated by Mago with
  `--generate-baseline --baseline <path>`, never hand-written, and never hand-edited. They carry the
  onboarding remainder that the safe fixer cannot clear: 931 lint findings in 361 entries and 115
  analyzer findings in 81 entries, both `variant = "loose"`. The per-rule, per-area breakdown is the
  burndown list and lives in the PR body. No entry is added by hand.
- `mago.bat`: copy verbatim. It is a tracked artifact, not an ignored one.
- Fix pass, in this order: `mago format` (plain `--fix`, never `--potentially-unsafe` or
  `--unsafe`), then `mago lint`, `mago analyze`, `mago guard`.
  - Guard remediation is D-3: move `Cli\Command` to `Cli\Commands`, rename `interface Command` to
    `interface CommandInterface`, update every reference in `src/`, `test/` and
    `bin/asciidoc-php-multi-repo`.
  - The safe fixer runs first. It clears the `redundant-cast`, `no-fully-qualified-global-class-like`
    and `no-redundant-use` families here, plus `prefer-early-continue` and `yoda-conditions` in the
    entry point. The remaining lint and analyze findings are genuine debt (assertion style, test
    attributes, named arguments, complexity metrics, unhandled thrown types, null-safety gaps) that
    needs per-site judgement, so they are baselined and burned down later in small PRs, per the
    preset's onboarding flow.
- The pre-migration bar is preserved for review: PHPStan was clean at `level: 10` over `src` and
  `bin/asciidoc-php-multi-repo` with `treatPhpDocTypesAsCertain: false`. The Mago gates pass with
  the baselines above, and `mago guard` passes with no baseline at all. The `possibly-*` analyzer
  findings in the baseline are exactly the class of issue that `treatPhpDocTypesAsCertain: false`
  suppressed, so removing the relaxation is a net tightening rather than a swap.
- `contracts/cli.md` is edited in the same commit as any change that adds or alters a flag, command
  or exit code, because `test/integration/ContractDocumentationTest.php` fails otherwise. This
  feature does not intend to change the CLI contract; the rename in D-3 is class-level only.
