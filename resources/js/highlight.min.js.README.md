# Vendored highlight.js build and theme

`highlight.min.js` in `resources/js` and `highlight.min.css` in `resources/css` are the upstream
highlight.js browser bundle and its GitHub light theme, published unchanged.

| Field | Value |
| --- | --- |
| Package | `@highlightjs/cdn-assets` |
| Version | 11.11.1 (bundle build `08cb242e7d`) |
| Bundle source | https://cdn.jsdelivr.net/npm/@highlightjs/cdn-assets@11.11.1/highlight.min.js |
| Theme source | https://cdn.jsdelivr.net/npm/@highlightjs/cdn-assets@11.11.1/styles/github.min.css |
| Upstream repository | https://github.com/highlightjs/highlight.js |
| Licence | BSD-3-Clause |
| Theme licence | BSD-3-Clause, `Theme: GitHub`, maintained by `@Hirse` |

The bundle carries the common language set and registers itself as `window.hljs`. Nothing is fetched
at runtime.

Two files here are this package's own work rather than vendored upstream code:

- `resources/js/highlight.js` is the loader. It highlights the listing blocks in the page and skips
  Mermaid blocks, which are rendered as diagrams instead.
- `resources/css/highlight-dark.css` is appended to the vendored theme at publish time, so the one
  published stylesheet carries the light tokens, the dark tokens, and the removal of the theme's own
  white fill. The dark palette is the GitHub dark syntax palette the vendored theme is drawn from.

Upgrading means replacing both vendored files and updating this table. The published asset names
carry a content hash, so a replacement invalidates the cached copies automatically.

Both payloads are emitted only on a page whose converted body contains a highlighted code block,
and only when `render.syntaxHighlighting` is on.
